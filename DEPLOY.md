# Веб-версія для команди: Vercel (фронт) + Render (бек)

## Як це влаштовано

```
Браузер (web/, Vercel) ──WebRTC: мікрофон і звук──► OpenAI GPT-Live
        │                                                ▲
        │ SDP-оффер                                      │ sideband (інструменти)
        ▼                                                │
Бекенд (server/, Render) ────────────────────────────────┘
   └─ інструменти сесії: голос, темп, мова, ім'я, кінець розмови, вебпошук, знання команди (Neon)
```

- **Звук іде напряму між браузером і OpenAI.** Затримка мінімальна, а браузер сам придушує ехо (`echoCancellation`), тож агент не перебиває сам себе.
- **Ключ OpenAI лише на бекенді.** Браузер надсилає свій SDP, бекенд створює сесію й повертає SDP-відповідь.
- **Інструменти виконує бекенд.** Він під'єднується до тієї ж сесії через sideband.
- **У кожного браузера своя розмова й налаштування.** Їх розрізняє випадковий id у `localStorage`.
- **Розмови зберігаються в базі (Postgres на Neon).** Після оновлення сторінки чи деплою розмова повертається, і Єва її пам'ятає. «Нова розмова» відкладає стару в «Історію» (`/history`, кнопка «Історія» в картці «Розмова»): там її можна перечитати, продовжити або видалити. Кожен браузер бачить лише свої розмови. Налаштування голосу — у браузері.

## 1. Render: бекенд

1. Render → **New → Blueprint** → цей репозиторій. Render підхопить `render.yaml`.
   - Або вручну: **New → Web Service**, Runtime **Python**:
     - Build: `pip install -r requirements-server.txt`
     - Start: `uvicorn server.app:app --host 0.0.0.0 --port $PORT`
     - Env: `PYTHON_VERSION=3.12.7`
2. Змінні середовища:

| Змінна | Значення |
|---|---|
| `OPENAI_API_KEY` | ключ OpenAI |
| `PUBLIC_BACKEND_URL` | `https://<ваш-сервіс>.onrender.com` (без `/` у кінці) |
| `FRONTEND_ORIGINS` | адреса з Vercel, напр. `https://voice-agent.vercel.app` (кілька — через кому) |
| `ACCESS_CODE` | пароль для команди. **Задайте обов'язково:** без нього будь-хто з посиланням витрачатиме ваш баланс OpenAI |
| `LOGS_TOKEN` | пароль прихованої сторінки `/logs` (історія дзвінків: репліки, нотатки, виклики інструментів з аргументами й результатами, відповіді бекенду). Без нього логи не віддаються нікому. Логи в пам'яті сервера: деплой чи перезапуск їх стирає; вкладка «Витрати» (хвилини й $ по днях і браузерах) — у базі, лишається |
| `MAX_SESSION_MINUTES` | межа однієї сесії GPT-Live, за замовчуванням 10 хв: забута вкладка не «їсть» хвилини довше. Справжня розмова не обривається — сторінка відкриває нову сесію з усією історією |
| `TIMEZONE` | часовий пояс для «сьогодні» й часу доби, за замовчуванням `Europe/Kyiv` |
| `WEB_SEARCH_API_KEY` | ключ Tavily для вебпошуку (той самий, що в Assistant-agent). Без нього Єва каже, що пошук недоступний |
| `DATABASE_URL` | рядок підключення до Postgres на Neon: «Знання» і всі розмови (див. нижче). Без нього вони лежать у файлах SQLite, які кожен деплой стирає |

3. Перевірка: `https://<ваш-сервіс>.onrender.com/healthz` → `{"ok":true}`.

> **Free-план Render засинає** після ~15 хв без запитів, перше відкриття сторінки «будить» його ~30–60 с. Для демо краще план Starter.

### База для «Знання» й розмов (Neon)

Таблиці: `kb_sets` і `kb_items` («Знання»), `conversations` (розмови, по рядку на розмову), `call_usage` (хвилини й токени кожного дзвінка — `/logs` → «Витрати»).

Сторінка «Знання» (`/knowledge`, кнопка «Знання» вгорі головної) зберігає набори записів: людей з віком,
хобі, улюбленими фільмами тощо. Єва шукає в них інструментом `knowledge_lookup`. Набори спільні для всіх,
хто має код доступу.

1. [neon.tech](https://neon.tech) → **New project**. Регіон — найближчий до сервісу на Render (Render за
   замовчуванням в Oregon → `AWS US West 2`).
2. **Connect** → скопіюйте рядок підключення (`postgresql://…?sslmode=require`).
3. Render → Environment → `DATABASE_URL` = цей рядок → Save (сервіс перезапуститься).
4. Перевірка: `/healthz` показує `"knowledge": "postgres"` і `"conversations": "postgres"`. Таблиці бекенд створює сам.

Без `DATABASE_URL` сторінка працює, але показує попередження: дані до першого деплою.

## 2. Vercel: фронт

1. У `web/config.js` впишіть адресу бекенду: `BACKEND_URL: "https://<ваш-сервіс>.onrender.com"`. Закомітьте.
2. Vercel → **Add New → Project** → цей репозиторій.
   - **Root Directory: `web`**
   - Framework Preset: **Other**, Build Command порожній, Output Directory порожній (статичні файли).
3. Після деплою скопіюйте адресу (`https://….vercel.app`) у `FRONTEND_ORIGINS` на Render і перезапустіть сервіс.

Разова перевірка з іншим бекендом без редеплою: `https://….vercel.app/?backend=https://інший.onrender.com`.

## 3. Як тестувати

1. Відкрити сторінку → ввести код доступу (якщо задано).
2. **«Почати розмову»** → дозволити мікрофон → «Привіт, Єва» → Єва вітається → говорити. «Дякую, Єва» — пауза, «Єва, скажи» — продовжити.
3. **«Консьєрж»** (перемикач угорі) — Єва сама вітається, питає ім'я, звіряє його зі «Знаннями» (однакові імена — питає прізвище) і ставить одне перевірочне питання; «Наступний гість» — з початку.
4. **`/chat`** (без посилання на сайті) — писати замість говорити: Єва відповідає голосом, мікрофон не потрібен. Та сама розмова й пам'ять, що й голосом.

## Локальний запуск веб-версії

```bash
uv sync --group server
# .env: OPENAI_API_KEY, PUBLIC_BACKEND_URL=http://localhost:8000
.venv/bin/python -m uvicorn server.app:app --port 8000      # Windows: .venv\Scripts\python.exe
# фронт: будь-який статичний сервер з папки web/, напр.
python -m http.server 5173 -d web   # і відкрити http://localhost:5173/?backend=http://localhost:8000
```

## Що відрізняється від десктопної версії

| Десктоп (`main.py`) | Веб |
|---|---|
| wake word «Єва, скажи» з локального мікрофона | кнопка «Почати розмову», далі «Привіт, Єва» (без розпізнавання фрази, напр. Firefox, — вітається сама), пауза й продовження — «Дякую, Єва» / «Єва, скажи» |
| локальний мікрофон, VAD і власний захист від ехо | браузер: WebRTC + вбудоване придушення ехо |
| налаштування в `assistant_memory.json` | налаштування в пам'яті сервера і в браузері |
